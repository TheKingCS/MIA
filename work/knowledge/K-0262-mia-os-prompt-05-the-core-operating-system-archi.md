What: fifteen documents in docs/mia_os/ (start at MIA_OS_CORE_ARCHITECTURE.md), DEC-0189 to DEC-0195 proposed, Q-47 to Q-51 for Zac, six proofs of concept described and not run. Planning only: nothing outside docs/ changed.

The shape: Linux underneath untouched (Fedora's KDE Atomic desktop as a bootc image built from a Containerfile in the repository; the distribution's kernel; no out-of-tree modules), MIA as user services and one session on top, one coordinator (the runtime, the only writer of the stores) with separate processes around it (shell, model server, system helper, capture agent, her browser, extensions, heavy jobs). No system unit requires a MIA unit.

Reasoning worth keeping: (1) Most 'privileged' things a desktop assistant wants are already allowed to the signed-in user by each service's own polkit policy (network, Bluetooth, power, user Flatpak installs), so the root helper can be tiny: only what Linux would ask an administrator's password for. (2) polkit's dialog is drawn by the session's agent outside MIA's process: a second confirmation MIA can't fake, which is the property that matters for an AI acting on a computer. Its rules live in the image, so nothing MIA reads can widen her powers at run time. (3) Reading system state needs no privilege on Linux, so 'MIA describes the machine' needs no helper. (4) Loopback TCP is reachable by every local program, sandboxed apps included: nothing is trusted for being local; a Unix socket gives caller identity for free. (5) An event between processes should say where the truth changed, never carry it; then duplicates and losses are harmless and no broker is needed. (6) Kernel pressure (PSI) is a better 'busy' signal than CPU percent. (7) cgroups can't limit VRAM: model routing must.

Found on the way: Fedora 45 (3 November 2026) packages ROCm and ollama-rocm itself, which overturns docs/HARDWARE.md's older 'Ubuntu because ROCm' (a note was added there); Ubuntu 26.04 also ships ROCm, so it's a real fallback. Fedora 45's system Python is 3.15, above MIA's 3.10 to 3.14: the image must carry MIA's own pinned Python and locked environment. cage shows one application, which conflicts with workspaces restoring apps and with prompts 23 and 24; DEC-0191 proposes KWin for both PC sessions, provisionally, with a proof of concept. bootc-native Fedora desktops aren't finished; deriving from the Kinoite container is the path others ship.

What to do next time: claims not read from a source on the day are marked '(to verify)' in the technology evaluation; check them in the proofs of concept before anything depends on them. The requirement mapping in the acceptance document was generated by a script kept only in the session's scratchpad; if requirements change, regenerate by the same rule (hand-map the rows Prompt 05 owns, a rule per category for the rest).
