The most private stores' files (at_rest.SEALED: conversations, memories, notes, life notes) are sealed with AES-256-GCM inside atomic_write_text, because every store already writes through it; reads go through at_rest.open_text, which reads sealed or plain, so a store moves at its next save with no migration step. The data key is 32 random bytes protected by Windows DPAPI in data/.keys/data_key.json: nothing to type at start, useless on another account or PC. Each envelope names its key id so a recovered key opens old files. What went wrong or nearly did: stores that can't read their file start empty and their next save replaces it, so a sealed file that won't open is copied aside before the error; a key file that won't open is never replaced (sealing stops and the security log alerts); sync compared raw bytes, which differ on every seal (random nonce), so sync and the /api/sync/file endpoints use open_bytes; tests that read conversations.json directly needed open_text. To seal another store: (1) add its file name to SEALED; (2) make its _load read through open_text; (3) **widen its except clause to catch ValueError** — this is the one that bites. open_text raises UnreadableFile, which is a ValueError, NOT a JSONDecodeError. A store that caught only `(json.JSONDecodeError, OSError)` would let UnreadableFile escape and crash MIA at boot when a sealed file can't open (a lost or changed key). Stages 1–3 found three stage-1 stores (conversations, journal, memories) that caught only JSONDecodeError and would have crashed; the parametrized test `test_a_sealed_store_whose_file_won_t_open_starts_empty_and_keeps_a_copy` now instantiates every sealed store with a wrong key and asserts it starts empty with the copy kept, so this can't regress. (4) add the store to SEALED_STORES in tests/test_at_rest.py (a test asserts SEALED and that list agree 1:1). (5) grep for any OTHER reader of the file name — `test_every_file_that_names_a_sealed_file_reads_it_with_open_text` fails the suite if a core/server/tools/modules/gui file names a sealed file and reads it without open_text, but TESTS that read the raw file (e.g. test_phone_history, test_talk_it_out, test_communication_gate) are not caught by it and must be converted to open_text by hand. Sealed by stage 3: conversations, memories, journal, life notes, people/pets, finances, insurance, GPS tracks, operating journal, turn traces, health, intents (reasons), communication log, freedom log, recreation, paths, browser routines. Not yet: the budget's files (blocked on the Plaid WIP in core/budget_manager.py). Game/XP stores (boss book, dungeon, quests, world map, rewards) were deliberately left unsealed — low privacy value, sync/game overhead.
