# Testing Guide — 4.4 Install Content Pack

## What changed

- `core/reference_library_manager.py` — new `install_pack_from_file()`
  and `PackInstallResult`. Validates before copying (real file, `.zim`
  extension, not already installed, opens successfully via libzim) the
  same validate-before-copy shape `core/module_validator.py` uses for
  module installs. On success, the freshly-copied file's `Archive` is
  cached immediately under its `pack_id`, bypassing the mid-copy
  quiet-period guard added for the earlier hang fix (see
  `docs/KNOWN_ISSUES.md`) — that guard exists for files some *other*
  process might still be writing; a file this method just finished
  copying itself is known-complete.
- `modules/knowledge/module.py` — new "Install Content Pack" button on
  the pack list header, next to Refresh. Opens a native file picker
  filtered to `*.zim`, calls the above, and shows a success/failure
  `QMessageBox`.

No worker thread — the install click blocks the UI for as long as the
copy takes, same as every other large-file copy in this codebase
(`core/backup_manager.py`'s restore, `module_manager`'s module-folder
copy). Revisit only if this becomes a real complaint on hardware.

## Part 1 — Automated tests

```bash
pytest tests/test_reference_library_manager.py -v
```

**Expected:** all pass, including
`test_install_pack_from_file_copies_and_lists_immediately`,
`_rejects_missing_file`, `_rejects_non_zim_extension`,
`_rejects_invalid_zim_content`, and `_rejects_duplicate_pack`.

## Part 2 — Manual click-through

1. Run `python main.py`, open **Knowledge**, click **Install Content
   Pack**, and pick any `.zim` file not already in your library
   (`reference_library/` by default).
   - **Expected:** a "Installed '<title>' successfully" dialog, and
     the pack appears in the list immediately — no delay, no need to
     click Refresh.
2. Click **Install Content Pack** again and pick the *same* file.
   - **Expected:** "Could not install this pack: A pack named
     '<filename>' is already installed." — nothing is copied twice,
     the existing pack is untouched.
3. Pick a non-`.zim` file (e.g. rename anything to `.txt` first, or
   pick one already visible in the file dialog before applying the
   filter).
   - **Expected:** "Not a .zim file — pick a file with a .zim
     extension." rejection, no crash.
4. Pick a `.zim`-named file that isn't actually a valid ZIM archive
   (e.g. `cp /bin/ls fake.zim`).
   - **Expected:** "Not a valid ZIM file: ..." rejection — nothing is
     copied into `reference_library/`.
