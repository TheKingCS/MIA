# Testing Guide — 2.7 Backup / Restore

## What changed

- `core/secrets_manager.py` — new: passphrase-based encryption
  (Fernet + PBKDF2), generic (not backup-specific) for future reuse.
- `core/backup_manager.py` — new: `create_backup()` / `restore_backup()`
  / `is_backup_encrypted()`. Backs up `config/config.json` + the whole
  `data/` directory into a single file, optionally encrypted.
- `modules/settings/module.py` — no longer a placeholder: "Backup Now"
  and "Restore from Backup" buttons.
- `gui/backup_dialog.py` — new: passphrase entry (with confirm) when
  creating a backup.
- `requirements.txt` — adds `cryptography` (only needed for this).

**Heads up:** restoring is destructive — it overwrites your current
`config/config.json` and replaces the entire `data/` directory
(profiles, notifications, etc.) with the backup's contents. Take a
backup of your *current* real state first if you want to get back to
it afterward.

## Part 1 — Plain (unencrypted) backup

1. Run `python main.py`, get to the main menu, click **Settings**.
2. Click **📦 Backup Now**.
3. In the dialog, leave "Encrypt this backup" **unchecked**, click OK.
4. Save the file somewhere easy to find, e.g. `~/mia_test_backup.zip`.
   - **Expected:** a "Backup Created" dialog confirming the file path.
5. Confirm the file actually exists and is a real zip:
   ```bash
   file ~/mia_test_backup.zip
   unzip -l ~/mia_test_backup.zip
   ```
   **Expected:** shows `manifest.json`, `config.json`, and `data/...`
   entries.

## Part 2 — Encrypted backup

1. Click **📦 Backup Now** again.
2. Check **"Encrypt this backup with a passphrase"**.
3. Enter a passphrase, then a **different** value in Confirm — click OK.
   - **Expected:** rejected with "Passphrases don't match!" — dialog
     stays open.
4. Now enter the same passphrase in both fields (e.g. `test1234`),
   click OK.
5. Save as `~/mia_test_backup.miabackup`.
   - **Expected:** "Backup Created" dialog, and the file is **not** a
     valid zip on its own:
     ```bash
     unzip -l ~/mia_test_backup.miabackup
     ```
     **Expected:** unzip reports it's not a zip file (it's encrypted —
     this is correct, not a bug).

## Part 3 — Restore a plain backup

1. Make a visible change first so you can confirm the restore actually
   did something — e.g. go to **Modules** and disable **Music**.
2. Go to **Settings**, click **♻ Restore from Backup**, select
   `~/mia_test_backup.zip` (the Part 1 file, made *before* you
   disabled Music).
   - **Expected:** no passphrase prompt (it's unencrypted), then a
     **Confirm Restore** warning dialog. Click **Yes**.
3. **Expected:** "Restore Complete" dialog telling you to restart.
4. Quit and relaunch `python main.py`.
   - **Expected:** Music is back on the main menu — the restore
     reverted the disable.

## Part 4 — Restore an encrypted backup

1. Click **♻ Restore from Backup**, select `~/mia_test_backup.miabackup`.
   - **Expected:** a passphrase prompt appears *before* the confirm
     dialog (the app detected it's encrypted without you telling it).
2. Enter the **wrong** passphrase.
   - **Expected:** after confirming the restore warning, a "Restore
     Failed" dialog with an error about an incorrect passphrase —
     your current config/data should be untouched.
3. Try again with the **correct** passphrase (`test1234` from Part 2).
   - **Expected:** confirm dialog, then "Restore Complete."

## Part 5 — Reject a non-backup file

1. Click **♻ Restore from Backup**, but pick some unrelated file (any
   random `.txt` or `.json` you have lying around — the file picker
   filters by extension by default, so you may need to switch it to
   "All Files").
   - **Expected:** no passphrase prompt, then either the confirm
     dialog followed by a clean "Restore Failed" error (not a crash),
     or — if you want to check without going through the confirm
     dialog — verify directly:
     ```bash
     cd ~/Projects/MIA
     python3 -c "
     from pathlib import Path
     from core.backup_manager import restore_backup
     result = restore_backup(Path('/etc/hostname'))
     print('passed:', result.passed)
     print('errors:', result.errors)
     "
     ```
     **Expected:** `passed: False` with a clear error, and your real
     `config/config.json` should be unchanged afterward.

## Cleanup

```bash
rm -f ~/mia_test_backup.zip ~/mia_test_backup.miabackup
```

## What to report back

- Did the plain backup (Part 1) produce a real, valid zip?
- Did the passphrase-mismatch check (Part 2) correctly reject
  mismatched passphrases before creating the file?
- Did restoring the plain backup (Part 3) actually revert your change
  after a restart?
- Did the encrypted restore (Part 4) correctly prompt for a passphrase
  unprompted, reject the wrong one without touching your data, and
  succeed with the right one?
- Did restoring a non-backup file (Part 5) fail cleanly instead of
  crashing or partially overwriting anything?
