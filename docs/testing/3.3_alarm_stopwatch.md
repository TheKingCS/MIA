# Testing Guide — 3.3 Alarm / Stopwatch

## What changed

- `core/alarm_manager.py` — new: `AlarmManager` (persisted CRUD alarm
  store, `data/alarms.json`) + `Alarm`. `check_due(now)` is pure logic
  (no Qt), called by a new periodic `QTimer` in `core/application.py`
  every ~20s so alarms fire regardless of which module/screen is
  active — a due alarm raises a regular notification through
  `NotificationManager` (toast + Notification Center), reusing that
  existing UI rather than building a new one.
- `core/app_context.py` — new `AppContext.alarms` field.
- `modules/toolbox/tools/alarm_tool.py` — new: the Alarm tool — a flat
  list of alarms with an inline checkbox to enable/disable, plus
  Add/Edit/Delete.
- `gui/add_edit_alarm_dialog.py` — new: label/time/repeat-days dialog.
- `modules/toolbox/tools/stopwatch_tool.py` — new: the Stopwatch tool
  — Start/Stop/Lap/Reset with a live readout and a lap list.
  Purely in-memory (no persistence — see design note below).
- `modules/toolbox/module.py` — Toolbox's **Tools** section now lists
  Calendar, Alarm, and Stopwatch.

**Design note — Stopwatch has no persistence.** Unlike Calendar/Alarm,
a stopwatch reading has no reason to survive an app restart. It does
survive *navigating away and back* within a session, though — Toolbox
caches built tool widgets, so the same `StopwatchTool` instance (and
its running `QTimer`) keeps ticking even while a different screen is
on top.

## Part 1 — Toolbox lists all three tools

1. Run `python main.py`, get to the main menu, click **Toolbox**.
   - **Expected:** the **Tools** section now lists **Calendar**,
     **Alarm**, and **Stopwatch**, above **Calculators**.

## Part 2 — Alarm: add, edit, enable/disable, delete

1. Open **Alarm**, click **Add Alarm**. Set a label, set the time to
   **1–2 minutes from now**, leave all day checkboxes unchecked
   (one-time), click OK.
   - **Expected:** the alarm appears in the list as
     `HH:MM  —  <label>  [Once]`, checkbox checked (enabled).
2. Wait for the set time to pass (stay on any screen — try leaving
   Toolbox entirely, e.g. open Notes, to confirm it's not
   screen-dependent).
   - **Expected:** within ~20s of the alarm's time, a notification
     toast appears ("Alarm: `<label>`" / "It's `HH:MM`."), and it's
     also in the Notification Center's list.
3. Go back to Toolbox → Alarm.
   - **Expected:** the alarm's checkbox is now unchecked (one-time
     alarms auto-disable after firing).
4. Uncheck/recheck an alarm's checkbox directly in the list (no
   dialog).
   - **Expected:** takes effect immediately, no dialog needed.
5. Select an alarm, click **Edit Selected**, change its time, click OK.
   - **Expected:** list updates; if it had auto-disabled from firing
     earlier, editing re-enables it (checkbox becomes checked again).
6. Select an alarm, click **Delete Selected**.
   - **Expected:** Yes/No confirm (defaulting to No); Yes removes it.
7. With nothing selected, click **Edit Selected** or **Delete
   Selected**.
   - **Expected:** an informational dialog, not a crash.
8. Add an alarm with one or more repeat days checked (e.g. today's
   day), let it fire.
   - **Expected:** unlike a one-time alarm, it stays enabled/checked
     after firing (it'll fire again next week on that day, not today
     again).

## Part 3 — Stopwatch

1. Open **Stopwatch**.
   - **Expected:** readout shows `00:00.0`, **Lap** disabled, **Reset**
     enabled.
2. Click **Start**.
   - **Expected:** button becomes **Stop**; readout counts up live;
     **Lap** becomes enabled, **Reset** becomes disabled.
3. Click **Lap** a couple of times at different moments.
   - **Expected:** each lap appears at the top of the list as
     `Lap N: <total> (+<delta since previous lap>)`.
4. Click **Stop**.
   - **Expected:** readout freezes; button becomes **Start** again;
     **Reset** re-enabled.
5. Click **Start** again (resume), let it run a bit, **Stop** again.
   - **Expected:** elapsed time continues accumulating from where it
     left off, not restarting from zero.
6. Navigate away (e.g. back to Toolbox list, open Calendar) while
   running, then come back to Stopwatch.
   - **Expected:** it's still running and shows the correct
     accumulated time (was ticking the whole time in the background).
7. Click **Reset**.
   - **Expected:** readout and lap list both clear to `00:00.0` / empty.

## What to report back

- Did Toolbox list all three tools under Tools (Part 1)?
- Did a one-time alarm fire as a notification at the right time
  regardless of the active screen, then auto-disable? Did a repeating
  alarm stay enabled after firing? Did inline enable/disable, edit,
  and delete all work, including the no-selection case (Part 2)?
- Did Stopwatch start/stop/lap/reset all work correctly, including
  resuming after a stop and continuing to run while navigated away
  (Part 3)?
