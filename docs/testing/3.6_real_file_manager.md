# Testing Guide — 3.6 Real File Manager

## What changed

- `modules/files_mod/module.py` — no longer a placeholder: a real file
  browser built on `QFileSystemModel` + `QTreeView`, starting at the
  user's home directory but able to navigate anywhere the OS permits.
- `modules/files_mod/file_operations.py` — new: pure logic for create/
  rename/delete/preview, testable without Qt.
- `gui/delete_confirm_dialog.py` — new: typed-confirmation dialog for
  permanent deletes (no trash/recycle bin — see design note below).
- `gui/file_preview_dialog.py` — new: text or image preview dialog.

**Design note — delete is genuinely permanent.** No trash/recycle bin
(would need an extra dependency, `send2trash`). Delete is gated behind
typing the exact item name to confirm, not just a Yes/No click.

## Part 1 — Browse and navigate

1. Run `python main.py`, click **Files**.
   - **Expected:** shows your home directory's contents in a sortable
     table (Name/Size/Type/Date Modified columns), path bar showing
     your home folder.
2. Double-click a folder.
   - **Expected:** navigates into it, path bar updates.
3. Click **↑ Up**.
   - **Expected:** returns to the parent folder.
4. Click **🏠 Home**.
   - **Expected:** returns to your home directory regardless of where
     you'd navigated to.
5. Type a valid folder path directly into the path bar and press Enter.
   - **Expected:** navigates there. Try an invalid path too — should
     show an error, not crash, and revert the path bar text.

## Part 2 — Create / Rename / Delete

1. Click **📁 New Folder**, name it something like `mia_test_folder`.
   - **Expected:** appears in the listing.
2. Select it, click **✏ Rename**, give it a new name.
   - **Expected:** renamed in place.
3. Select it, click **🗑 Delete**.
   - **Expected:** a confirm dialog appears, requiring you to **type
     the exact name** before OK becomes clickable. Try typing the
     wrong text first (OK should stay disabled), then the correct
     name (OK becomes enabled) — confirm deletes it.

## Part 3 — Preview

1. Double-click a `.txt` (or similar plain-text) file.
   - **Expected:** a preview dialog shows the file's content in a
     monospace, read-only view.
2. Double-click an image file (`.png`/`.jpg`/etc.), if you have one handy.
   - **Expected:** a preview dialog shows the image, scaled to fit.
3. Double-click some other file type (e.g. a binary or unrecognized
   extension).
   - **Expected:** a simple "File Info" dialog with size/type — not a
     crash, not an attempted text dump of binary data.

## Part 4 — Search / filter

1. In the "Filter this folder…" box, type part of a filename you know
   exists in the current folder.
   - **Expected:** the list narrows live to matching items (both files
     *and* folders — an earlier version only filtered files, since
     `QFileSystemModel`'s default filter setting makes directories
     bypass name filters unless explicitly told not to).
2. Clear the filter box.
   - **Expected:** the full listing returns.

## What to report back

- Did browsing/navigation work correctly, including invalid-path
  handling (Part 1)?
- Did create/rename/delete all work, with delete requiring the typed
  confirmation (Part 2)?
- Did text and image preview both work, with a graceful fallback for
  other file types (Part 3)?
- Did the search filter narrow both files and folders (Part 4)?
