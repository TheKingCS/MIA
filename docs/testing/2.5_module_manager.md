# Testing Guide — 2.5 Module Manager UI Upgrade

## What changed

- `core/module_manager.py` — `is_enabled()`, `set_enabled()`, `enabled_modules()`, `rescan()`
- `config/default_config.json` — new `modules.disabled` key
- `modules/module_browser/module.py` — enable/disable toggle per row, "Rescan Modules" button
- `gui/main_window.py` — main menu grid now shows only *enabled* modules; live-rebuilds via the event bus when modules change (no restart needed); `closeEvent` properly unsubscribes (learned from the earlier notification bug)

## Part 1 — Disable a module and confirm it disappears from the main menu live

1. Run `python main.py`, get to the main menu. Note the modules currently shown (should be all 9).
2. Click **Modules**.
3. Find a module you don't need right now — e.g. **Music** — and click its **Disable** button.
   - **Expected:** the row updates immediately to show "(disabled)" with a reddish border, and the button now says "Enable".
4. Click **Main Menu** (or Back) to return to the grid.
   - **Expected:** **Music is gone from the grid** — no restart was needed.

## Part 2 — Re-enable it

1. Go back into **Modules**.
2. Click **Enable** on the Music row.
3. Return to the main menu.
   - **Expected:** Music is back in the grid immediately.

## Part 3 — Confirm the safety rule (Modules screen can't be disabled)

1. In the Modules screen, find the row for **Modules** itself (`module_browser`).
   - **Expected:** its **Disable** button should be greyed out / disabled, with a tooltip explaining why if you hover over it.
2. As a backend double-check (not just a UI restriction):
   ```bash
   cd ~/Projects/MIA
   python3 -c "
   from core.config_manager import ConfigManager
   from core.event_bus import EventBus
   from core.app_context import AppContext
   from core.module_manager import ModuleManager

   config = ConfigManager()
   context = AppContext(config=config, events=EventBus())
   manager = ModuleManager(context)
   manager.discover()
   result = manager.set_enabled('module_browser', False)
   print('set_enabled result:', result)
   print('still enabled:', manager.is_enabled('module_browser'))
   "
   ```
   **Expected output:** `set_enabled result: False` and `still enabled: True` — confirming the refusal happens at the core level, not just hidden in the UI.

## Part 4 — Persistence across restart

1. Disable Music again (per Part 1).
2. Fully quit the app and relaunch: `python main.py`.
   - **Expected:** Music is still missing from the main menu — the disabled state survived the restart.
3. Check it directly in config:
   ```bash
   cat config/config.json | grep -A3 '"modules"'
   ```
   Should show `"disabled": ["music"]` (or similar).
4. Re-enable Music via the Modules screen when you're done testing, so it doesn't stay hidden.

## Part 5 — Rescan (optional, more involved)

This one requires creating a throwaway test module folder, so treat it as optional if you're short on time.

1. Create a minimal new module while the app is still running:
   ```bash
   cd ~/Projects/MIA
   mkdir -p modules/test_rescan_module
   touch modules/test_rescan_module/__init__.py
   cat > modules/test_rescan_module/module.py << 'EOF'
   from __future__ import annotations
   from gui.widgets.placeholder_widget import build_placeholder_widget
   from modules.module_base import ModuleBase

   class TestRescanModule(ModuleBase):
       module_id = "test_rescan_module"
       display_name = "Rescan Test"
       description = "Temporary module for testing Rescan."
       icon = "\U0001F9EA"

       def get_widget(self):
           return build_placeholder_widget(self.display_name, self.description, self.icon)
   EOF
   ```
2. Without restarting the app, go to **Modules** and click **Rescan Modules**.
   - **Expected:** a status message like "Found 1 new module(s)." appears, and "Rescan Test" now shows up in the module list.
3. Go to the main menu.
   - **Expected:** "Rescan Test" now appears in the grid too, without a restart.
4. Clean up the test module when done:
   ```bash
   rm -rf modules/test_rescan_module
   ```
   (This won't remove it from the *running* app's menu until restart — that's expected, since rescan only detects additions, not removals.)
