# Testing Guide — 2.3 Notification Center

## What changed

- `core/notification_manager.py` — new service: `notify()`, persisted to `data/notifications.json`
- `core/app_context.py` — `AppContext.notifications` field
- `core/application.py` — constructs `NotificationManager`
- `gui/notification_toast.py` — brief pop-up shown when a notification is raised while the app is open
- `gui/notification_center.py` — full list, opened from the bell button
- `gui/main_window.py` — 🔔 bell button with unread count, plus a fix: `closeEvent` now unsubscribes from the event bus so "Switch User" rebuilding the window doesn't leave stale callbacks behind

## Part 1 — Raise a test notification while the app is running

With `python main.py` already running, open a **second terminal**, `cd` into the same project folder, activate the venv, and run:

```bash
cd ~/Projects/MIA
source .venv/bin/activate
python3 -c "
from core.config_manager import ConfigManager
from core.event_bus import EventBus
from core.app_context import AppContext
from core.notification_manager import NotificationManager

config = ConfigManager()
context = AppContext(config=config, events=EventBus())
notifications = NotificationManager(context)
notifications.notify('Test Alert', 'This is a test notification.', level='warning', source='manual_test')
print('Notification raised.')
"
```

**Important limitation to understand first:** this second process has its own separate `EventBus` instance — it is *not* connected to the running app's live event bus, so **no toast pop-up will appear** from this alone. What it *does* test is the persistence layer: the notification gets written to `data/notifications.json` on disk.

1. In the running app, click the **🔔 bell button** in the header.
   - **Expected:** the notification list opens and shows "Test Alert" — even though it was raised from a separate process, because both read/write the same `data/notifications.json` file. (It won't show live/instantly without reopening the dialog, since the running app doesn't currently poll the file — that's expected for this milestone, not a bug.)
2. Confirm the bell badge cleared after opening the dialog (opening it marks everything read).
3. Click the "×" on that entry to dismiss it, confirm it disappears from the list.

## Part 2 — Test the live toast pop-up (same process)

This is the more important test — a notification raised *from within the running app itself*, the way a real module will do it later.

1. Quit the app if it's running.
2. Temporarily add this test line near the end of `MainWindow.__init__` in `gui/main_window.py` (right after `self._setup_notifications()`):
   ```python
   self.context.notifications.notify("Welcome", "MIA core is online.", level="info", source="system")
   ```
3. Run `python main.py`.
   - **Expected:** shortly after the main menu appears, a small toast should pop up in the top-right corner reading "Welcome — MIA core is online.", with a teal left border (info level), and disappear on its own after about 5 seconds.
4. Check the bell button — it should now show **🔔 1**.
5. Click it, confirm the entry appears, and that the badge clears after closing the dialog.
6. **Remove the test line you added** once confirmed, so it doesn't fire on every future boot.

## Part 3 — Switch User doesn't leave stale event subscriptions

This tests the cleanup fix specifically.

1. Run `python main.py`, then click "Switch User" a few times in a row (switching back and forth between profiles, or just opening/closing the selector).
2. Check `logs/mia.log` for anything unusual:
   ```bash
   tail -50 logs/mia.log
   ```
   You should **not** see repeated errors about "Error in subscriber for event 'notification.created'" or similar — if you do, the unsubscribe isn't working and duplicate/stale subscriptions are piling up.
