# Testing Guide — 3.1 Calculator Engine

## What changed

- `core/calculator_engine.py` — new: `CalculatorEngine` (registry) +
  `CalculatorPlugin` (base class for a single calculator), the shared
  service described in `docs/ROADMAP.md`'s "Shared core services" table.
- `core/app_context.py` — new `AppContext.calculators` field.
- `core/application.py` — registers the two built-in calculators.
- `modules/toolbox/module.py` — new: the `Toolbox` module, a browsable
  list of registered calculators grouped by category.
- `modules/toolbox/calculators/unit_converter.py` — new: Unit Converter
  (Length, Weight, Temperature).
- `modules/toolbox/calculators/ohms_law.py` — new: Ohm's Law (solve
  for voltage, current, or resistance given the other two).
- `gui/styles.py` — new `QLabel#ReadoutLabel` style shared by both
  calculators' result display.

## Part 1 — Toolbox lists calculators grouped by category

1. Run `python main.py`, get to the main menu, click **Toolbox**.
   - **Expected:** two category headers — **Electronics** (Ohm's Law)
     and **General** (Unit Converter) — each with a row showing the
     calculator's name, description, and an **Open** button.

## Part 2 — Ohm's Law

1. Open **Ohm's Law**.
2. Leave "Solve for" on **Voltage**, enter Current = `2`,
   Resistance = `5`, click **Calculate**.
   - **Expected:** Result: `10 V`, and the Voltage field itself fills
     in with `10`.
3. Change "Solve for" to **Current**. The Current field should clear
   and become editable; Voltage and Resistance should still hold their
   values (or re-enter if needed) — enter Voltage = `10`,
   Resistance = `5`, click **Calculate**.
   - **Expected:** Result: `2 A`.
4. Try entering text (not a number) in one of the input fields, click
   **Calculate**.
   - **Expected:** a clear "enter valid numbers" message, not a crash.
5. Click **← Back to Toolbox**.
   - **Expected:** returns to the calculator list.

## Part 3 — Unit Converter

1. Open **Unit Converter**.
2. Category = Length, From = Meters (m), To = Feet (ft), Value = `1`.
   - **Expected:** Result updates live (no button needed) to
     approximately `3.281 ft`.
3. Switch Category to **Temperature**.
   - **Expected:** the From/To dropdowns repopulate with Celsius/
     Fahrenheit/Kelvin — not still showing length units.
4. From = Celsius (°C), To = Fahrenheit (°F), Value = `0`.
   - **Expected:** Result: `32 °F`.
5. Clear the Value field entirely.
   - **Expected:** Result resets to `—` (not an error/crash).
6. Unit Converter now has 13 categories total (Length, Area, Volume,
   Weight, Temperature, Speed, Pressure, Energy, Power, Time, Data
   Storage, Angle, Fuel Economy) — the exact conversion math for every
   category is covered by `tests/test_unit_converter.py` (46 tests as
   of this writing), so a full manual walkthrough of each isn't
   necessary here. Worth a quick browse through the Category dropdown
   to confirm they all appear and the From/To lists repopulate for
   each, but trust the automated tests for correctness.

## Part 4 — Navigation round-trip

1. From a calculator, go back to Toolbox, open the *other* calculator,
   go back again, then leave Toolbox entirely (Home / open another
   module from the main menu) and return to Toolbox.
   - **Expected:** no crash; the list (or whichever screen was last
     active) displays correctly either way.

## What to report back

- Did Toolbox correctly group both calculators by category (Part 1)?
- Did Ohm's Law solve correctly for at least two different targets,
  and fail cleanly on bad input (Part 2)?
- Did Unit Converter convert correctly and handle a category switch
  and an empty value gracefully (Part 3)?
- Any crash navigating in and out of Toolbox repeatedly (Part 4)?
