# Testing Guide — 2.4 Global Search

## What changed

- `core/search_manager.py` — new service: `register_provider()`, `search()`
- `core/app_context.py` — `AppContext.search` field
- `core/application.py` — constructs `SearchManager`, registers two providers: modules and profiles
- `gui/search_dialog.py` — the search-anywhere dialog, live search-as-you-type
- `gui/main_window.py` — 🔍 Search header button + `Ctrl+K` shortcut
- `docs/ADDING_MODULES.md` — documents how future modules register their own searchable content

## What's searchable right now (and what isn't yet)

Right now, search covers **modules** (by name/description) and
**profiles** (by name). It does *not* yet search notes, files, or
reference content — those modules are still placeholders with no real
content to index. That's expected, not a bug; this milestone builds
the search **infrastructure** so those can plug in later with one line
each, per the new section in `docs/ADDING_MODULES.md`.

## Part 1 — Search finds a module by name

1. Run `python main.py`, get to the main menu.
2. Press **Ctrl+K** (or click the **🔍 Search** button in the header).
3. Type `map`.
   - **Expected:** a result appears for "Maps" with its description, under a "Modules" label.
4. Click that result.
   - **Expected:** the dialog closes and you're taken straight into the Maps module — same as if you'd clicked its button on the main menu.

## Part 2 — Search finds a module by partial/description text, not just name

1. Open search again (Ctrl+K).
2. Type `offline` (this word appears in several module descriptions, not names).
   - **Expected:** multiple results appear (e.g. Maps, Knowledge) — confirming search matches descriptions, not just the display name.

## Part 3 — Search finds a profile by name

This needs at least one other profile to exist. If you only have one profile right now:

```bash
cd ~/Projects/MIA
python3 -c "
from core.config_manager import ConfigManager
from core.event_bus import EventBus
from core.app_context import AppContext
from core.profile_manager import ProfileManager

config = ConfigManager()
context = AppContext(config=config, events=EventBus())
profiles = ProfileManager(context)
profiles.create_profile('TestSearch', make_active=False)
print('Created profile for search testing.')
"
```

1. Open search (Ctrl+K), type `TestSearch`.
   - **Expected:** a result appears under "Profiles" reading "Switch to this profile."
2. Click it.
   - **Expected:** the search dialog closes and the full profile selector screen opens (not an instant switch — this is intentional, see the code comment in `main_window.py`'s `_on_search_result_activated` for why).

## Part 4 — No false positives / empty states

1. Open search, type something nonsensical like `zzzznotarealthing`.
   - **Expected:** "No matches." shown, not an error or blank screen.
2. Clear the search box entirely.
   - **Expected:** results list clears back to empty (not showing every module).

- Did clicking a profile result open the profile selector?
