# Testing Guide — 2.9 Boot Animation

## What changed

- `gui/boot_core_widget.py` — new: `PulsingCoreWidget`, a 440x440
  glowing orb that breathes (brightens/dims via a looping sine wave),
  with "MIA" rendered directly in its center.
- `gui/splash_screen.py` — rebuilt around the core widget: no separate
  "MIA" title label anymore (it's in the core graphic now), bigger
  subtitle text, wider progress bar, and no more `setFixedSize()` — it
  now resizes to fill the screen in kiosk mode.
- `core/application.py` — the splash now goes through `_display()`
  (the same kiosk-mode-aware fullscreen routing every other screen
  uses) instead of a plain `.show()`; boot step status text was
  reworded to an all-caps HUD style; step timing doubled to 1400ms/step
  (5.6s total) so the animation has time to actually register.

## Part 1 — Fullscreen (kiosk mode on)

1. Confirm `kiosk_mode` is `true`: `grep kiosk_mode config/config.json`.
2. Run `python main.py`.
   - **Expected:** the splash screen fills the entire display — not a
     small centered window. The pulsing core (with "MIA" inside it)
     should be clearly visible and legible, roughly centered, with
     "Multifunctional Intelligent Assistant" above it and the status
     text below.
3. Watch the full ~5.6s sequence.
   - **Expected:** status text cycles through 4 HUD-style messages
     ("INITIALIZING CORE SYSTEMS...", "SYNCING CONFIGURATION
     MATRIX...", "SCANNING MODULE ARRAY...", "ENGAGING INTERFACE...")
     while the core visibly breathes (brightens/dims) a couple of
     times per step. No flashing/flicker, no visible tearing.
4. After boot, confirm it hands off correctly to whatever screen is
   next for your current setup (lock screen / profile selector / main
   window) — the animation change shouldn't affect this handoff logic
   at all, just what's shown while it happens.

## Part 2 — Non-kiosk (windowed) fallback still works

1. Temporarily set `"kiosk_mode": false` in `config/config.json` (or
   toggle it if a Settings UI exists for it yet — currently it doesn't,
   so hand-edit is expected here).
2. Run `python main.py`.
   - **Expected:** the splash shows as a normal centered window (not
     fullscreen), same animated core, same behavior otherwise — this
     confirms the fullscreen change didn't break the everyday dev
     workflow (`kiosk_mode: false` is very likely your default outside
     of testing).
3. Set `kiosk_mode` back to `true` (or whatever it was) afterward.

## Part 3 — No leftover timer/crash on fast transitions

1. Run `python main.py` a few times in a row, letting it fully boot
   each time (don't force-kill mid-splash).
   - **Expected:** no crash, no warning in `logs/mia.log` about a
     "QTimer" or similar after the splash closes — `PulsingCoreWidget`
     stops its own animation timer in `SplashScreen.closeEvent()`.

## What to report back

- Did the splash genuinely fill the screen in kiosk mode (Part 1)?
- Was "MIA" legible inside the pulsing core, and did the breathing
  animation read clearly at the new timing?
- Did the non-kiosk windowed fallback still work correctly (Part 2)?
- Any crash or warning after repeated boots (Part 3)?
