# Testing Guide — 2.2b Profile Management (Switch User, Passwords, Delete)

Builds on `docs/testing/2.2_user_profiles.md`. Do this after that guide
has already passed.

## What changed

- `core/profile_manager.py` — password hashing (PBKDF2-HMAC-SHA256, salted, never plaintext) and safe delete (archives data, refuses to delete the last profile or without the right password)
- `gui/password_dialog.py` — reusable password prompt
- `gui/lock_screen.py` — new: gates boot when the *sole* profile has a password (otherwise a single-profile password would never be checked)
- `gui/add_profile_dialog.py` — optional password field when creating a profile
- `gui/profile_select.py` — clicking a protected profile now prompts for its password; each profile row has a delete button (disabled if it's the only one)
- `gui/main_window.py` — new "⇄ Switch User" header button
- `core/application.py` — wires it all together

## Back up first

```bash
cp config/config.json config/config.json.backup2
```

## Part 1 — Switch User button

1. Run `python main.py` — should boot straight to the main menu as before (you likely still have just your one profile from last time).
2. Click **"⇄ Switch User"** in the header.
   - **Expected:** the main window closes and the "Who's using MIA?" selector appears — even though you only have one profile. This is intentional: Switch User always shows the selector, since it's also how you add a 2nd profile.
3. Click "+ New Profile", create a second profile (no password for now).
4. Click your original profile in the list.
   - **Expected:** selector closes, main menu reappears, greeting your original name.
5. Click "Switch User" again, this time pick the new profile.
   - **Expected:** main menu reappears greeting the *new* name.

## Part 2 — Password on profile creation + selector gating

1. Click "Switch User" → "+ New Profile".
2. Enter a name, check "Protect this profile with a password", enter a password, click OK.
3. From the selector, click that new profile.
   - **Expected:** a password prompt appears before it activates.
4. Enter the **wrong** password.
   - **Expected:** an "Incorrect Password" warning; you're returned to the selector, nothing activates.
5. Click it again, enter the **correct** password.
   - **Expected:** it activates normally, main menu appears.

## Part 3 — The lock screen (single protected profile)

This is the case worth testing carefully, since it's the one place a bug would make a password silently meaningless.

1. Use "Switch User" → delete every profile except the password-protected one from Part 2 (see Part 4 below for how deletion works). You should end up with exactly one profile, and it has a password.
2. **Fully quit and restart the app**: `python main.py`.
   - **Expected:** since there's only one profile, it should skip the "Who's using MIA?" selector entirely — but a **lock screen** ("Welcome back, `<name>`" with a password field) should appear instead of going straight to the main menu.
3. Enter the wrong password.
   - **Expected:** "Incorrect password. Try again." message, field clears, stays on the lock screen.
4. Enter the correct password.
   - **Expected:** main menu appears normally.

## Part 4 — Deletion safety

1. With 2+ profiles present, click "Switch User", then click the trash icon next to a profile **without** a password.
   - **Expected:** a confirmation dialog ("Delete Profile... archived, not permanently erased"). Confirm it.
   - **Expected:** that profile disappears from the list immediately.
2. Try deleting a **password-protected** profile.
   - **Expected:** it asks for that profile's password before the delete confirmation takes effect. Wrong password → deletion refused with a warning; correct password → deleted.
3. Get down to exactly one remaining profile and look at its row.
   - **Expected:** the trash icon should be **disabled** (greyed out) — you should not be able to delete the last profile on the device.
4. Confirm deleted data wasn't actually erased:
   ```bash
   ls data/profiles/
   ```
   You should see folders like `_deleted_<id>_<timestamp>/` for anything you deleted — the original data is archived there, not gone.
