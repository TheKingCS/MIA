# Testing Guide — 2.6 System Logs Viewer

## What changed

- `modules/diagnostics/module.py` — no longer a placeholder; reads and
  displays `logs/mia.log` in-app, with a level filter, a text filter,
  and a manual refresh button.
- `gui/styles.py` — new `QComboBox` styling and a monospace
  `QPlainTextEdit#LogView` style for the log display.

## Part 1 — Open the log viewer and see real log lines

1. Run `python main.py` and get to the main menu.
2. Click **Diagnostics**.
   - **Expected:** a scrollable, monospace log view appears, already
     populated with recent log lines (timestamps, `[LEVEL   ]`, logger
     name, message) — the same lines you'd see in `logs/mia.log` or on
     the console. It should already be scrolled to the bottom (most
     recent line visible).
   - The info line above the log view should read something like
     "Showing N of N lines (most recent 1000 lines of .../logs/mia.log)."

## Part 2 — Level filter

1. Change the **Level** dropdown from `ALL` to `INFO`.
   - **Expected:** only lines containing `[INFO    ]` remain. The count
     in the info line above should drop accordingly.
2. Try `WARNING` or `ERROR` — if none exist yet in this session's log,
   the view should just go empty (not error out).
3. Set it back to `ALL`.

## Part 3 — Text filter

1. Type a word you know appears in the log (e.g. `module` or a module
   name like `notes`) into the filter box.
   - **Expected:** the view live-updates to only lines containing that
     text (case-insensitive), as you type.
2. Clear the filter box.
   - **Expected:** the full (level-filtered) view returns.

## Part 4 — Refresh picks up new activity

1. With Diagnostics still open, leave it, do something that logs a new
   line — e.g. go to **Modules** and disable/enable a module (this
   logs an INFO line), or just navigate around the app.
2. Return to **Diagnostics** and click **🔄 Refresh**.
   - **Expected:** the new line(s) appear at the bottom of the log view.

## Part 5 — Missing log file doesn't crash

This one's hard to trigger without deleting your real log file, so
treat it as optional / a code-read sanity check rather than something
to force: `modules/diagnostics/module.py`'s `tail_lines()` returns `[]`
for a nonexistent path rather than raising, and the module shows "No
log file found yet at ..." instead of crashing. If you want to verify
it directly:

```bash
cd ~/Projects/MIA
python3 -c "
from pathlib import Path
from modules.diagnostics.module import tail_lines
print(tail_lines(Path('does_not_exist.log'), max_lines=10))
"
```

**Expected output:** `[]`

## What to report back

- Did opening Diagnostics show real, correctly formatted log lines,
  scrolled to the bottom?
- Did the Level filter correctly narrow the view?
- Did the text filter correctly narrow the view, live, case-insensitively?
- Did Refresh pick up newly logged activity?
