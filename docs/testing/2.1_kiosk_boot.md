# Testing Guide — 2.1 Kiosk Boot Infrastructure

Covers: fullscreen kiosk mode, the systemd auto-start service, crash
recovery, and the maintenance exit shortcut.

## What changed

- `config/default_config.json` — new `system.kiosk_mode` flag (default `false`)
- `gui/main_window.py` — enters fullscreen on show when `kiosk_mode` is on; `Ctrl+Shift+Q` exits with confirmation
- `main.py` — logs uncaught exceptions before crashing, so failures are visible in logs even after a restart
- `deploy/mia.service` — systemd user service template (crash-restart via `Restart=always`)
- `deploy/install_kiosk.sh` / `deploy/uninstall_kiosk.sh` — setup/teardown

## Part 1 — Test on your desktop/WSL first (no Pi needed)

You don't need the actual Pi to test the fullscreen/shortcut behavior.

1. Manually flip the flag on in your existing config:
   ```bash
   python3 -c "
   from core.config_manager import ConfigManager
   c = ConfigManager()
   c.set('system.kiosk_mode', True)
   c.save()
   "
   ```
2. Run `python main.py`.
   - **Expected:** after the splash/setup sequence, the main window opens **fullscreen with no window border/title bar**.
3. Press **Ctrl+Shift+Q**.
   - **Expected:** a confirmation dialog appears ("Exit MIA and return to the desktop?").
4. Click **No**.
   - **Expected:** dialog closes, app stays open and fullscreen, nothing else happens.
5. Press **Ctrl+Shift+Q** again, click **Yes**.
   - **Expected:** the app closes cleanly.
6. Turn kiosk mode back off for normal development:
   ```bash
   python3 -c "
   from core.config_manager import ConfigManager
   c = ConfigManager()
   c.set('system.kiosk_mode', False)
   c.save()
   "
   ```

## Part 2 — Test the crash-logging behavior

1. Temporarily break something on purpose, e.g. add `raise RuntimeError("test crash")` near the top of `MIAApplication.run()` in `core/application.py`.
2. Run `python main.py`. It should crash immediately.
3. Check `logs/mia.log` — you should see a `CRITICAL` entry with a full traceback for "test crash".
4. **Remove the line you added** and confirm `python main.py` runs normally again.

## Part 3 — Test on the actual Raspberry Pi 5

Requires: Raspberry Pi OS installed, MIA cloned, and
`pip install -r requirements.txt` already run inside a `.venv` in the
project folder (the installer checks for this and will tell you if
it's missing).

1. On the Pi:
   ```bash
   cd mia
   bash deploy/install_kiosk.sh
   ```
   Expected output ends with a "Done" block showing the useful
   `systemctl`/`journalctl` commands.

2. Check the service is actually running:
   ```bash
   systemctl --user status mia
   ```
   Expected: `Active: active (running)`.

3. Reboot the Pi:
   ```bash
   sudo reboot
   ```
   **Expected:** after boot, the Pi logs in automatically (no login
   prompt) and MIA appears fullscreen within a few seconds — no
   desktop, taskbar, or manual step required.

4. **Crash-recovery test** — find the process and kill it hard:
   ```bash
   pkill -9 -f main.py
   ```
   **Expected:** within ~3 seconds (per `RestartSec=3` in `mia.service`),
   MIA relaunches automatically and shows the main menu (or setup
   wizard, if config was somehow lost) again.

5. Confirm the crash was logged:
   ```bash
   journalctl --user -u mia -n 50 --no-pager
   ```
   You should see the service stop and restart events.

6. Test the exit shortcut on-device: press **Ctrl+Shift+Q**, confirm
   **Yes**. **Expected:** the app closes, then systemd restarts it
   automatically within a few seconds (this is correct and expected
   behavior — it confirms `Restart=always` works even for a clean exit;
   if you want a way to exit *without* auto-restart for real
   maintenance, use `systemctl --user stop mia` from an SSH session
   instead of the in-app shortcut).

## Part 4 — Reverting

```bash
bash deploy/uninstall_kiosk.sh
```

Confirm `systemctl --user status mia` now reports the unit as not
found/inactive, and that `python main.py` run manually opens in a
normal (non-fullscreen) window again.

## Known limitations to note (not bugs)

- This relies on Raspberry Pi OS's default desktop session for the
  display — it is not a fully custom minimal Wayland kiosk session.
  That's an intentional simplicity trade-off (see comments in
  `deploy/install_kiosk.sh`).
- `Ctrl+Shift+Q` followed by "Yes" **will** cause an immediate
  restart, by design — it's a "restart MIA" shortcut more than a
  true "quit," which is appropriate for a kiosk device. Use SSH +
  `systemctl --user stop mia` for maintenance where you don't want it
  to come back immediately.
