# Testing Guide — 4.2 Reference Library UI

## What changed

- `modules/knowledge/module.py` — no longer a placeholder: a pack list
  (every `.zim` file `core.reference_library_manager
  .ReferenceLibraryManager` discovers) and, per pack, a reader screen
  (in-pack search box + article viewer), same
  list-page/`QStackedWidget`/cached-detail-page pattern as
  `modules/toolbox/module.py`.
- `modules/knowledge/zim_text_browser.py` — new: a `QTextBrowser`
  subclass that resolves ZIM content via `AppContext.reference_library`
  instead of the filesystem.
- `modules/knowledge/zim_url.py` — new: pure `QUrl <-> (pack_id,
  entry_path)` conversion backing the browser's custom `zim://` scheme.
- `tests/run_module.py` — fixed to wire up
  `calendar`/`alarms`/`journal`/`inventory`/`reference_library`/`search`
  on its `AppContext`, matching `core/application.py`'s real boot.
  Before this it silently crashed on `notes` and any Toolbox tool too
  (`context.search`/etc. was always `None`) — worth knowing if you've
  hit that before and assumed it was your own module's bug.

## Part 1 — Automated tests

```bash
pytest tests/test_zim_url.py -v
```

**Expected:** all pass — pure `QUrl`/`zim://` conversion logic,
including the relative-link-resolution behavior the whole in-page
navigation feature depends on.

`modules/knowledge/module.py` and `zim_text_browser.py` themselves
have no pytest coverage, by the same convention every other module's
Qt widget code follows (see `tests/` — there are no `QApplication`-level
widget tests anywhere in this repo). Part 2 below is the real check.

## Part 2 — Manual click-through

You need at least one real `.zim` file in `reference_library/` — reuse
whatever you copied there for milestone 4.1's manual test
(`docs/testing/4.1_reference_library_engine.md`), ideally one with more
than one linked page so you can exercise navigation.

1. `python tests/run_module.py knowledge`
   - **Expected:** a pack list showing your installed pack(s) with
     title, article count, and language pulled from the ZIM's own
     metadata (not just the filename).
2. If `reference_library/` is empty, run it anyway.
   - **Expected:** "No reference packs installed yet. Copy .zim files
     into: `<path>`" — the path shown should be the real
     `reference_library/` folder, and the app shouldn't crash on an
     empty library.
3. Click **Open** on a pack.
   - **Expected:** the reader screen shows the pack's main page,
     rendered on a plain white/black-text background (deliberately
     not the app's dark theme — see `zim_text_browser.py`'s docstring
     for why).
4. Click an in-page link to another article.
   - **Expected:** navigates to that article. The **‹** (back) button
     in the top nav row becomes enabled.
5. Click **‹**.
   - **Expected:** returns to the previous page; **›** (forward)
     becomes enabled. Click **›** to go forward again.
6. Type a word you know appears in a *different* article than the one
   currently shown into the search box.
   - **Expected:** a results list appears below the search box with
     matching article titles. Clear the search box — the results list
     should disappear.
7. Click a search result.
   - **Expected:** navigates the article viewer to that entry, and the
     search box/results list clear.
8. Click **← Back to Reference Library**.
   - **Expected:** returns to the pack list. Reopen the same pack.
   - **Expected:** returns to wherever you left the reader (cached
     page, not rebuilt from the main page again) — matches Toolbox's
     existing tool-caching behavior.
9. If your test pack has an article with embedded images, scroll to one.
   - **Expected:** the image renders. If it doesn't, check whether the
     image is an SVG — `QImage` can't decode those, a known limitation
     of the `QTextBrowser` approach (see `docs/ROADMAP.md`'s v0.4
     breakdown), not a bug to chase for this milestone.

## Design notes worth knowing before building 4.3/4.4

- The pack list re-scans `reference_library/` on every **Refresh**
  click (and on first build) — there's no cached/stale index to keep
  in sync, since `core/reference_library_manager.py` itself doesn't
  cache `list_packs()` results either.
- `ZimTextBrowser.loadResource()` branches on MIME type, not the
  `resource_type` argument Qt passes in — simpler and already covers
  both HTML and image resources correctly (verified against real
  `libzim`-generated fixtures during development).
