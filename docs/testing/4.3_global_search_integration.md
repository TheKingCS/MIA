# Testing Guide — 4.3 Global Search Integration

## What changed

- `modules/knowledge/module.py` — registers a Global Search provider
  in `on_load()`, same `action_type="open_module"` pattern as
  `modules/notes/module.py`. Caps results at 3 hits per installed pack
  and 15 total, since `gui/search_dialog.py` has no result-count cap
  of its own and a single Wikipedia-selection pack can have hundreds
  of thousands of articles.

## Part 1 — Automated tests

No new pytest coverage — `_search()` is a thin wrapper around
`core/reference_library_manager.py`'s already-tested `search()`
(`tests/test_reference_library_manager.py`), with no new pure logic to
isolate. Run the full suite to confirm nothing regressed:

```bash
pytest -q
```

## Part 2 — Manual click-through

Requires at least one real `.zim` pack in `reference_library/` — see
`docs/testing/4.1_reference_library_engine.md`/`4.2_reference_library_ui.md`.

1. Run `python main.py`, press **Ctrl+K** (or the header search
   button), and type a word you know appears in an installed pack's
   content (e.g. a common medical term if you have a medicine pack
   installed).
   - **Expected:** results appear labeled with the article title and,
     as the description, the *pack's* title (not the app description)
     — e.g. "Diabetic foot • WikiMed Medical Encyclopedia".
2. Click a Knowledge result.
   - **Expected:** navigates to the Knowledge module's pack list (not
     directly into the article — this is the same "land on the list,
     not a deep link" tradeoff Notes already makes; see this
     milestone's `docs/ROADMAP.md` entry for why).
3. With multiple large packs installed, type a very common word (e.g.
   "the" or a common topic word likely to hit in more than one pack).
   - **Expected:** at most 15 results total, at most 3 from any single
     pack — the dialog should never lag or show hundreds of rows.
4. Type something present in no installed pack.
   - **Expected:** "No matches." (or other providers' results only,
     if the term happens to match a module name/profile) — no crash,
     no empty Knowledge-sourced rows.
