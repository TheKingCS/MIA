# Testing Guide — 3.2 Calendar

## What changed

- `core/calendar_manager.py` — new: `CalendarManager` (persisted CRUD
  event store, `data/calendar_events.json`) + `CalendarEvent`. Follows
  the same durability pattern as `core/notification_manager.py`.
- `core/app_context.py` — new `AppContext.calendar` field.
- `core/application.py` — constructs `CalendarManager` alongside
  `NotificationManager`.
- `modules/toolbox/tool_base.py` — new: `ToolboxTool`, the base for a
  built-in Toolbox tool (parallel to, but separate from,
  `CalculatorPlugin` — a tool is a stateful CRUD screen, not a
  formula).
- `modules/toolbox/tools/calendar_tool.py` — new: the Calendar tool —
  a `QCalendarWidget` month grid (marked dates have events) plus an
  agenda panel for the selected date (Add/Edit/Delete).
- `gui/add_edit_event_dialog.py` — new: title/date/all-day-or-time/
  notes dialog, used for both creating and editing an event.
- `modules/toolbox/module.py` — Toolbox now lists a **Tools** section
  (Calendar) above **Calculators**; open/back navigation is shared
  between both kinds of item.

## Part 1 — Toolbox lists Calendar under Tools

1. Run `python main.py`, get to the main menu, click **Toolbox**.
   - **Expected:** a **Tools** section (Calendar) appears above the
     **Calculators** section (Electronics/General, unchanged from
     3.1) — same row style (name, description, **Open** button).

## Part 2 — Adding an event

1. Open **Calendar**.
   - **Expected:** a month grid on the left (today's date visible/
     selectable) and an agenda panel on the right showing "Events on
     `<today's date>`" and "No events."
2. Click **Add Event**. Enter a title, leave **All day** checked,
   click OK.
   - **Expected:** dialog closes; the event appears in the agenda list
     as "All day — `<title>`"; today's cell on the grid is now
     bold/colored.
3. Click **Add Event** again on the same date, uncheck **All day**,
   set a time earlier than the first event's (if the first was all-
   day, add a second timed event to compare against), click OK.
   - **Expected:** both events appear in the agenda, all-day event(s)
     listed before timed ones, timed ones in time order.
4. Click **Add Event**, try to click OK with the title left empty.
   - **Expected:** dialog does not close; a clear empty-title
     indication (placeholder text change), no crash.

## Part 3 — Editing and deleting

1. Select an event in the agenda list, click **Edit Selected**, change
   its title and/or date, click OK.
   - **Expected:** agenda updates; if the date changed, the grid jumps
     to (and selects) the new date, and the old date's marker
     disappears if that was its last event.
2. With no agenda item selected, click **Edit Selected** or **Delete
   Selected**.
   - **Expected:** an informational dialog ("Select an event...") —
     not a crash.
3. Select an event, click **Delete Selected**.
   - **Expected:** a Yes/No confirm dialog (defaulting to No); Yes
     removes it from the agenda and, if it was the date's last event,
     clears that date's grid marker.

## Part 4 — Navigating months and persistence

1. Add an event on a date next month, then use the grid's navigation
   arrows to page to next month.
   - **Expected:** the new event's date is marked; paging back to the
     current month still shows this month's markers correctly (no
     stale or missing marks either direction).
2. Go back to Toolbox, open a calculator, go back, reopen Calendar.
   - **Expected:** no crash; previously added events and grid markers
     are still there (cached page, not rebuilt).
3. Close and restart the app (`python main.py`), open Toolbox →
   Calendar.
   - **Expected:** all events created in this session are still
     present — confirms `data/calendar_events.json` persistence.

## What to report back

- Did Toolbox show Calendar under a Tools section above Calculators
  (Part 1)?
- Did adding events work, including empty-title validation and
  correct all-day-first/time ordering (Part 2)?
- Did edit and delete work correctly, including the no-selection case
  (Part 3)?
- Did month navigation keep grid markers accurate, and did events
  survive an app restart (Part 4)?
