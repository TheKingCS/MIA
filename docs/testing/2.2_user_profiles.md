# Testing Guide — 2.2 User Profiles

Covers: the new `ProfileManager` service, migration of your existing
single-user config, the profile-select screen, and adding a second profile.

## What changed

- `core/profile_manager.py` — new service: create/list/activate profiles, legacy migration
- `core/app_context.py` — `AppContext.profiles` field
- `core/application.py` — boot flow now branches: setup wizard (first run) → profile selector (2+ profiles) → straight to main window (exactly 1 profile, the common case)
- `gui/setup_wizard.py` — now creates the first profile instead of setting a flat `user.name`
- `gui/profile_select.py`, `gui/add_profile_dialog.py` — new screens, only shown when 2+ profiles exist
- `config/default_config.json` — `user` section replaced by `profiles: {}` and `system.active_profile_id`
- `gui/main_window.py` — header greeting now reads the active profile's name

## Important — back up your config first

You already have a real `config.json` from testing 2.1. Before testing
this milestone, make a backup so you can restore it if anything looks
wrong:

```bash
cp config/config.json config/config.json.backup
```

## Part 1 — Test the migration (your exact upgrade scenario)

1. Pull in the updated files (see below for what to replace).
2. Run `python main.py`.
3. **Expected:** it should **not** show the setup wizard again — it
   should go straight to the main menu, and the header should still
   greet you by the same name you entered before.
4. Confirm the migration actually happened in config:
   ```bash
   cat config/config.json
   ```
   You should see a `"profiles"` section now containing your name
   under a generated ID, and `"system": {"active_profile_id": "..."}`
   pointing at it. The old `"user"` section may still be present too —
   that's harmless leftover, not a bug.

If it *does* show the setup wizard again, something about the
migration didn't fire — stop and let me know what your `config.json`
looked like before this test, rather than continuing.

## Part 2 — Test adding a second profile

There's no in-app "add profile" button on the main menu yet (that's
Settings module territory, still a placeholder) — for now, add one
directly to exercise the profile-selector screen:

```bash
python3 -c "
from core.config_manager import ConfigManager
from core.event_bus import EventBus
from core.app_context import AppContext
from core.profile_manager import ProfileManager

config = ConfigManager()
context = AppContext(config=config, events=EventBus())
profiles = ProfileManager(context)
profiles.create_profile('Test User', make_active=False)
print('Profiles now:', [p.name for p in profiles.list_profiles()])
"
```

Then run `python main.py` again.

**Expected:** instead of going straight to the main menu, you should
now see a **"Who's using MIA?"** screen listing both profiles as
buttons, plus a "+ New Profile" button.

1. Click "+ New Profile", type a name, click OK.
   - **Expected:** a third profile button appears in the list immediately, no restart needed.
2. Click one of the profile buttons.
   - **Expected:** the selector screen closes and the main menu appears, greeting you by that profile's name.
3. Close and re-run `python main.py`.
   - **Expected:** since there are still 3 profiles, the selector screen appears again (by design — with multiple profiles, MIA always asks who's using it, rather than remembering last time).
