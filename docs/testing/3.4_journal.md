# Testing Guide — 3.4 Journal

## What changed

- `core/journal_manager.py` — new: `JournalManager` (persisted CRUD
  entry store, `data/journal_entries.json`) + `JournalEntry`. Built as
  a `core/` shared service (like `CalculatorEngine`), per
  `docs/ROADMAP.md`'s "Notes/Journal Engine" row, even though only
  Notes uses it today — future modules (Project Manager, Lab notes,
  vehicle notes) are meant to reuse `self.context.journal` directly.
- `core/app_context.py` — new `AppContext.journal` field.
- `gui/add_edit_journal_entry_dialog.py` — new: title/tags/body dialog.
- `modules/notes/module.py` — no longer a placeholder: a filterable
  list of entries (title, tags, last-updated) with Add/Edit/Delete.
  Also the first module to register its own Global Search provider
  (`on_load()` → `self.context.search.register_provider("notes", ...)`,
  the pattern documented in `docs/ADDING_MODULES.md` but not
  previously used by any module).

**Design note — search deep-linking.** Selecting a journal entry from
Ctrl+K search opens the Notes module (same `action_type="open_module"`
as the "modules"/"profiles" providers), not a deep link to that
specific entry — a more specific action would need a new
`action_type` and a branch in `gui/main_window.py`'s
`_on_search_result_activated`, deliberately deferred rather than
added speculatively. Also note: entries are only searchable *after*
you've opened Notes at least once in the current session — `on_load()`
only runs on first activation (lazy init), an existing framework
behavior, not specific to this module.

## Part 1 — Add / Edit / Delete

1. Run `python main.py`, click **Notes**.
   - **Expected:** empty list, a filter box, and Add/Edit/Delete
     buttons.
2. Click **Add Entry**. Enter a title, some tags (comma-separated,
   e.g. `idea, project-x`), and some body text, click OK.
   - **Expected:** the entry appears in the list as
     `<title>  [<tags>]   (<date time>)`.
3. Click **Add Entry**, try to click OK with the title left empty.
   - **Expected:** dialog does not close; placeholder text changes to
     indicate the problem, no crash.
4. Select the entry, click **Edit Selected**, change its title/tags/
   body, click OK.
   - **Expected:** the list row updates, and the displayed timestamp
     changes (confirms `updated_at` bumped).
5. With nothing selected, click **Edit Selected** or **Delete
   Selected**.
   - **Expected:** an informational dialog, not a crash.
6. Select the entry, click **Delete Selected**.
   - **Expected:** a Yes/No confirm (defaulting to No); Yes removes it.

## Part 2 — Filter

1. Add three or four entries with distinct titles/tags/body text.
2. Type part of one entry's title into the filter box.
   - **Expected:** the list narrows live to just the matching entry
     (or entries).
3. Clear the filter, type part of a tag instead (not present in the
   title/body).
   - **Expected:** still matches correctly.
4. Type part of some body text.
   - **Expected:** still matches correctly.
5. Clear the filter box entirely.
   - **Expected:** the full list returns, newest-updated first.

## Part 3 — Global Search integration

1. With Notes already opened at least once this session (so its
   search provider is registered), press the search shortcut / open
   Ctrl+K.
2. Type text matching one of your journal entries' title, tag, or body.
   - **Expected:** a result appears (source "Notes"), showing the
     entry's tags (or "Journal entry" if it has none) as its
     description.
3. Select it.
   - **Expected:** opens the Notes module (not a crash) — it does not
     deep-link to the specific entry, just lands on the list (see
     design note above).

## What to report back

- Did add/edit/delete all work correctly, including empty-title
  validation and the no-selection case (Part 1)?
- Did the live filter correctly match on title, tags, and body text
  (Part 2)?
- Did a journal entry show up in Global Search results and correctly
  open Notes when selected (Part 3)?
