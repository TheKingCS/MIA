## 3. Prompt 17's own checks (the skeptical review, 17b §10)

| Question | Answer |
|---|---|
| Have we designed anything that doesn't need to exist? | Yes: a model-serving node, spatial portals, the extensions host and the Forge pipeline are long-term and are **not** in the MVP, Alpha or Beta. Several Prompt 13 and 14 documents describe the same mechanisms twice; the blueprint keeps one reference for each |
| Are we duplicating Linux? | No: logins, windows, settings, updates, encryption, sandboxing and supervision are the OS's. MIA adds a session entry, a helper with fixed operations, and her own app |
| Custom infrastructure without justification? | The helper (justified: polkit has no fixed-operation broker for this). Nothing else |
| Is the first release too complicated? | It was; it's now re-tiered (67 of 97 stay at the MVP gate) |
| Can one developer maintain it? | Only with the CI gates and the VM test running unattended (FW-01, FW-02) and the image staying Fedora's with additions |
| Can we reproduce a build? | Not yet (C-17). FW-01 |
| Can we recover when MIA fails? | In design, yes (Plasma session, the OS without MIA). Proven headless only; FW-03 proves the graphical fallback |
| Can we migrate without loss? | Not yet proven; FW-07 rehearses it, then REQ-IMP-009 gates the real move |
| Can we run without a cloud? | Yes: no cloud is configured in the MVP |
| Can we replace models without rebuilding MIA? | Yes: models are Ollama tags in settings (DEC-0206), never in the image |
| Can we add apps and devices without redesign? | Apps: yes (the registry, manifests). Devices: yes, with WP-10's device records |
| Can every consequential action be independently authorized? | In MIA, yes (tiers, grants, approval cards). At the OS level, only once FW-06's helper exists |
| Can we prove requirements are met? | Partly: the matrix ties each to a verification. The image-level evidence starts with FW-02 |
| Can we say what to build first? | Yes: FW-01 |
