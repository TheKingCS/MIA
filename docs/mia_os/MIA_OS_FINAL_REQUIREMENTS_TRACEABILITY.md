# MIA OS: final requirements traceability (Prompt 17)

*Claude (Opus), 2026-11-18. Version 1.0. Generated from the requirement tables by the script kept with Prompt 17's
work, so no requirement can drop out. The matrix (`MIA_OS_REQUIREMENTS_TRACEABILITY_MATRIX.md`, regenerated by
`python -m tools.requirements_matrix`) stays the register of every requirement; this document governs **which
release's gate each open Must · MVP requirement belongs to** and **which work package delivers it** (DEC-0276).*

## 1. The register

491 requirements: Exists 176, Partial 165, New 111, Planned 39.
By tier: MVP 268, R1 214, Mature 7, Later 2.
Must · MVP: 260, of which 97 earlier ones are not yet Exists, plus Prompt 17's own new ones (§5, REQ-IMP-007 to 013: all at the MVP gate except REQ-IMP-011, R1).

**What "Exists" means (corrected).** A status of Exists means the behaviour is in the code and tested on Windows
(or in CI). It does **not** mean verified on the MIA OS image. The MVP gate re-verifies every Exists requirement it
names on the image (FW-02 runs the suite inside the VM image; MV-02 on his PC). Three evidence levels are recorded
from now on: *in code*, *verified on Linux*, *verified on the image* (DEC-0276).

## 2. Open Must · MVP requirements by release

Re-tiering the 97 earlier open requirements (Codex F-03: the MVP was too broad to audit; Prompt 17's own seven are in §5): **MVP** 67, **Alpha** 26, **Beta** 4.
Alpha and Beta are the releases after the MVP (`MIA_OS_FINAL_MVP_AND_RELEASE_DEFINITION.md`). Moving a
requirement to Alpha keeps it a Must; it leaves the first install's gate, not the plan.
